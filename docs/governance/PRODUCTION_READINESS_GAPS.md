# Production-readiness gaps

> Honest register. "Implemented" means code exists AND tests prove it in this repository.
> Nothing here implies regulatory compliance.

## Implemented (tested in this branch)

- Capability model mirrored from canonical API roles; deny-by-default authorisation helper.
- 18-stage typed care-journey engine with blockers + optimistic concurrency + audit/timeline effects.
- Feature-flag resolver with 7-layer precedence and global kill switch.
- Unified application shell: flag → session → capability route guards (client UX gate).
- Timeline event model with query-layer visibility filtering.
- Audit events with metadata redaction (PHI-safe).
- Slice-1 server spine: referrals → triage → intake → assessment → signed note → outcome,
  with synthetic consent/transcript/AI-draft provenance (in-memory persistence).

## Partially implemented

- **Server flag enforcement**: implemented as middleware; no admin control surface yet for
  privileged flag changes (capability + reason + audit UI pending `feat/admin-control-centre`).
- **Notifications**: generated by the workflow engine and recorded, but no delivery channel
  (email/SMS) is wired.
- **Permissions**: enforced server-side via `requirePermission`; organisation-scoped overrides
  exist in `@neurocare/permissions` but no org config store is wired.
